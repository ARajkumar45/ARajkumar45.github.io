01

Bolna Voice Agent: ATM Issue Desk

StackPython, Docker, Redis, Deepgram, OpenAI, FastAPI

StatusIn progress · Oct 2026

Code and results on GitHub ↗

Problem
Phone calls are the hard case for speech-to-text: 8 kHz mu-law audio and call-center noise. With Bolna’s default settings (Deepgram Nova-2), word error rate on ATM-support sentences was 5.7%.
Built
Ran the open-source Bolna stack locally in Docker (agent server, Redis, Deepgram speech-to-text and text-to-speech, OpenAI LLM) and traced a call through its source. Built a mock bank API in FastAPI and an ATM issue-desk agent with five tools: card status, block card, balance, mini statement and complaint registration. The caller must confirm before a card is blocked.
Measured
30 recorded ATM-support sentences, converted to 8 kHz phone-quality audio, with and without call-center noise. 180 test transcriptions scored for word error rate with jiwer.
Result
5.7% → 2.6% by moving to Nova-3 with en-IN and 30 banking keyterms. Along the way I found and traced three framework issues:
  • Deepgram voice rejected with HTTP 400 when a mu-law codec was paired with a 24 kHz default sample rate.
  • The call endpoint reports success even when Twilio rejects the call.
  • The Docker build installs upstream code instead of the fork.

02

Adversarial AI Evaluation Pipelines

WhereHandshake AI, independent contractor, remote

StatusApr 2026 – present

Problem
A benchmark task is only useful if it is hard for the right reason: a model should fail because of its reasoning, not because of a weak verifier, a flaky environment or a leaked answer.
Built
End-to-end evaluation pipelines around a 30-check adversarial rubric across five quality families, each check with a CI-verifiable mutation probe and automated QC gates. Reproducible Docker environments with runtime-injected hidden datasets, anti-cheat controls and hash-pinned inputs, targeting sub-40% model accuracy.
Measured
Oracle verification and mutation testing in CI, 37 executable QC checks, and pass@k calibration. Tasks use compensatory fault architectures: four interdependent bugs, so a partial fix does not pass.
Result
6 accepted ML benchmark tasks (4 interdependent bugs, pass@5 = 0.200). Also ran side-by-side model comparisons with evidence-based rationales, and built guardrail and safety verification across containerized AI environments.
The rubric: 30 checks, 5 families
  1. IOracle correctness
  2. IIContract coherence
  3. IIIVerifier rigor
  4. IVEnvironment determinism
  5. VAnti-cheat isolation
